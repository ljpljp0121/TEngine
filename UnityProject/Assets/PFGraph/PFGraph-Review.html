总体判断

8.1/10

作为“Unity 编辑器内的可视化图框架”，PFGraph 的结构完整度很高。它不是轻量玩具，而是已经具备 MVVM、命令系统、端口求值、黑板、子图入口、复制粘贴、分组、便签、垫板、MiniMap、Inspector 等能力的框架。

一句话

PFGraph 更像一个“自研版 NodeGraphProcessor 基础框架”，而不是 xNode 那种低样板、字段驱动的小框架。

优点是架构边界清楚、编辑器体验可控、二次开发空间大；代价是学习成本更高，GraphView 实验 API、Odin 依赖、运行时执行引擎缺失等问题需要补齐。

适合 技能编辑器、行为树编辑器、数据流/配置图、自研工具链
谨慎 需要开箱即用执行引擎、强社区生态、低维护成本的项目

最强点

Model / ViewModel / View 分层清晰，Model 数据很薄，端口与行为集中在 Processor。后续扩业务时不会太快变成一团编辑器脚本。

最大短板

PFGraph 当前是编辑器框架，不是运行时图执行引擎。它有 pull 式端口求值，但没有完整的拓扑执行、状态机、异步节点、调度器。

首要修复

补齐 Odin 依赖声明或去掉 Odin；整理 package.json；修复 Blackboard 的 HashCode 比较；明确 GraphView/Unity 版本策略。

1. 项目结构

PFGraph 的目录基本按 Unity Package 分层组织，Runtime 和 Editor 分开，有 asmdef，Resources 下放 UXML/USS/纹理，Examples 下放三类示例。

目录定位关键内容评价
Runtime/Common 通用基础设施 ViewModel、Bindable、EventStation、Blackboard、CommandDispatcher、ObjectPool、反射缓存、Snowflake ID 基础设施偏完整，但部分通用代码与图框架耦合度可以再收敛。
Runtime/Core 图核心模型与处理器 BaseGraph、BaseNode、BasePort、BaseConnection、BaseGraphProcessor、BaseNodeProcessor、PortProcessor、命令、属性 项目的主心骨。Model 很轻，Processor 承担行为，是可维护性来源。
Runtime/Graph Unity 集成层 IGraphAsset、IGraphAssetOwner、GraphAssetOwner、GraphRuntimeUtil、GraphValidationUtil 资产与运行时对象之间的桥。适合继续扩成运行时执行入口。
Editor/Scripts/Graph 编辑器图 UI BaseGraphWindow、BaseGraphView、BaseNodeView、BasePortView、NodeMenuWindow、Inspector、默认 View 功能面已经超过基础 GraphView 示例，包含工具栏、Inspector、ItemLibrary、MiniMap、复制粘贴等。
Resources/GraphProcessor 编辑器 UI 资源 GraphWindow.uxml、BasicStyle.uss、节点/端口/连接/便签/分组样式、纹理、Skin 把视觉资源从代码拆出去是正确方向。
Examples 样例与验证 MathExample、FlowExample、PerfTest 覆盖数据流、流程图、性能测试。问题是示例依赖 Sirenix/Odin，但 package.json 未声明。
Documentation~ 包文档 架构、使用指南、GAS 扩展、ShaderGraph 扩展、设计审查 文档量很足，是这个项目的加分项。

2. 架构链路

Model

BaseGraph / BaseNode / BaseConnection

负责序列化数据：画布 zoom/pan、节点列表、连线列表、分组、便签、垫板。节点只内置 id 和 position，业务字段由节点子类追加。

ViewModel

BaseGraphProcessor / BaseNodeProcessor / PortProcessor

负责节点创建、连线校验、端口求值、黑板、事件、诊断、Undo/Redo 命令接入。端口在 Processor 构造里动态创建。

View

BaseGraphWindow / BaseGraphView / BaseNodeView

基于 UnityEditor.Experimental.GraphView 和 UI Toolkit。负责绘制、菜单、拖拽、选择、复制粘贴、Inspector、MiniMap。

核心数据流

1. 创建资产ScriptableObject 实现 IGraphAsset，保存 BaseGraph 子类。
2. 打开窗口BaseGraphWindow.Open(asset) 根据 GraphType 找 CustomView 窗口。
3. 生成 VMViewModelFactory 扫描 [ViewModel]，把 Model 包装成 Processor。
4. 生成 ViewGraphProcessorEditorUtil 扫描 [CustomView]，创建对应 UI。
5. 命令修改CommandDispatcher 执行 Add/Move/Connect/Remove 并支持 Undo。

设计亮点

  • 端口动态化：端口不写死在 Model 字段中，而是在 Processor 中用 AddPort 创建，这让同一节点可按配置生成不同端口。
  • 连接有校验：TryValidateConnection 检查空端口、方向、同端口自连、类型兼容，优于很多裸 GraphView 教程。
  • 求值有防护：PortProcessor.GetConnectionValue<T> 带 ThreadStatic evaluation stack/cache，可发现循环依赖并减少重复求值。
  • 资产保存策略清楚：编辑时克隆 Graph，保存时写回 IGraphAsset，避免打开编辑器窗口时直接污染资产。
  • 扩展点集中：[NodeMenu]、[NodeTitle]、[ViewModel]、[CustomView] 四类属性基本覆盖节点注册、业务、展示。
这套分层比 xNode 的字段端口方式更重，但更适合做大型工具。它的维护关键是继续保持“Model 只存数据，Processor 管逻辑，View 管交互”的边界，不要为了赶功能把业务塞回 View。

3. 扩展方式

PFGraph 的标准扩展路径是“Graph Model + Graph Asset + Graph Window/View + Node Model + Node Processor + 可选 Node View”。最小闭环如下。

A. 新建一种 Graph

using System;
using PFGraph;
using UnityEngine;

[Serializable]
public class SkillGraph : BaseGraph
{
    public string graphVersion = "1.0";
}

[CreateAssetMenu(menuName = "PFGraph/Skill Graph")]
public class SkillGraphAsset : ScriptableObject, IGraphAsset
{
    [SerializeField] private SkillGraph data = new SkillGraph();

    public Type GraphType => typeof(SkillGraph);
    public BaseGraph LoadGraph() => data;
    public void SaveGraph(BaseGraph graph) => data = (SkillGraph)graph;
}

B. 绑定编辑器窗口

using PFGraph;

[CustomView(typeof(SkillGraph))]
public class SkillGraphWindow : BaseGraphWindow
{
    protected override BaseGraphView NewGraphView()
    {
        return new SkillGraphView();
    }
}

public class SkillGraphView : DefaultGraphView
{
    protected override bool IsCompatible(BasePortView from, BasePortView to, NodeAdapter adapter)
    {
        return base.IsCompatible(from, to, adapter);
    }
}

C. 定义节点与 Processor

using PFGraph;

[NodeMenu("Skill/Apply Damage")]
[NodeTitle("Apply Damage")]
[NodeTooltip("Apply a damage value to the target")]
public class ApplyDamageNode : BaseNode
{
    public float defaultDamage = 10f;
}

[ViewModel(typeof(ApplyDamageNode))]
public class ApplyDamageNodeProcessor : BaseNodeProcessor, IGetPortValue<float>
{
    public ApplyDamageNodeProcessor(BaseNode model) : base(model)
    {
        AddPort(new PortProcessor("Target", BasePort.Direction.Left, BasePort.Capacity.Single, typeof(object)));
        AddPort(new PortProcessor("Damage", BasePort.Direction.Left, BasePort.Capacity.Single, typeof(float)));
        AddPort(new PortProcessor("Out", BasePort.Direction.Right, BasePort.Capacity.Multi, typeof(float)));
    }

    public float GetValue(string portName)
    {
        var model = (ApplyDamageNode)Model;
        return Ports["Damage"].GetConnectionValue<float>() is var value && value != 0f
            ? value
            : model.defaultDamage;
    }
}

D. 可选自定义节点 View

using PFGraph;
using UnityEngine.UIElements;

[CustomView(typeof(ApplyDamageNode))]
public class ApplyDamageNodeView : DefaultNodeView
{
    protected override void DoInit()
    {
        var label = new Label("Damage");
        controls.Add(label);
    }
}
扩展目标推荐扩展点注意事项
新增节点类型BaseNode + [NodeMenu] + [ViewModel]端口名必须唯一；端口在 Processor 构造中创建。
新增节点 UI[CustomView(typeof(MyNode))] + BaseNodeView使用 controls / container 添加 UI，并监听 ViewModel 变化。
限制可连接端口重写 BaseGraphView.IsCompatible运行时连接也会走 BaseGraphProcessor.TryValidateConnection。
新增图级变量BaseGraph 子类字段或 Blackboard需要考虑序列化和 Undo/Redo。
做运行时执行新增 IGraphExecutor / 节点执行接口当前框架只提供编辑与 pull 求值，不提供完整调度器。

4. 使用方式

编辑器内使用

  • 创建实现 IGraphAsset 的 ScriptableObject 资产。
  • 双击资产会进入 BaseGraphWindow.OnOpen，自动打开对应窗口。
  • 右键空白处创建节点，拖拽端口创建连接。
  • 用 Ctrl+Z/Ctrl+Y 撤销重做，Ctrl+S 保存。
  • Inspector 面板查看图统计、诊断、选中元素和 Blackboard。

代码内使用

  • 通过 ViewModelFactory.ProduceViewModel(graph) 得到 BaseGraphProcessor。
  • 通过 AddNodeCommand、ConnectCommand、RemoveElementsCommand 修改图结构。
  • 通过 Ports["X"].GetConnectionValue<T>() 做数据流求值。
  • 通过 GraphValidationUtil.Repair 修复丢失节点、失效连线等历史数据。

当前示例

示例说明可学习点
MathExample Float、Add、Sub、Log 等节点组成简单数据流。 学习 IGetPortValue<float>、自定义 NodeView、资产双击打开。
FlowExample 行为开始节点、动画状态节点，偏行为树/流程图风格。 学习流端口、节点菜单过滤、自定义保存/复制逻辑。
PerfTest 批量节点、求值、连接、复制等性能测试。 学习大图性能压力点和端口求值缓存。

5. 与常见图编辑器工具对比

这里对比的是定位，不是简单“谁更好”。xNode 更轻，NodeGraphProcessor 更成熟，Unity Graph Toolkit 更官方，PFGraph 更适合你掌控全套编辑体验。

维度 PFGraph xNode NodeGraphProcessor Unity Graph Toolkit
定位 自研通用图编辑器框架 轻量 Unity 节点图框架 数据处理图框架 Unity 官方前端框架
UI 技术 UI Toolkit + Experimental GraphView IMGUI/自研编辑器体系 UIElements + GraphView Unity 官方 Graph Toolkit
端口模型 Processor 动态 AddPort 字段标记 [Input]/[Output] 字段属性 + PortData + 自定义端口行为 官方工具模型，偏前端框架
样板代码 中高 低 中 中高
运行时执行 无完整执行引擎，只有 pull 求值 通常由用户实现节点逻辑 内置 graph processor / dependency order 支持编译到 runtime model，但不含 runtime execution backend
编辑器能力 MiniMap、Inspector、ItemLibrary、Blackboard、Group、Note、Placemat、Copy/Paste 轻量、易上手，扩展较直接 参数、组、便签、Relay、Stack、菜单、Inspector 等更成熟 官方交互与 UX 规范，适合新 Unity 版本
风险 依赖实验 GraphView、Odin 未声明、生态少 最新 Release 较老，复杂工具要自己补很多 第三方依赖，框架范式较固定 Unity 版本要求高，仍需自建业务逻辑/执行后端
最适合 想自控架构和 UI 的团队内部工具 快速做对话、FSM、简单可视化配置 数据处理、依赖图、复杂编辑器工具 Unity 6.x 以后，希望走官方路线的新工具

PFGraph 相对 xNode 的优缺点

优势

  • MVVM 分层更明确，复杂编辑器不会很快失控。
  • 端口可以动态构造，适合技能、条件、复合节点、可变输入。
  • 编辑器功能更多，内置 Inspector、ItemLibrary、Blackboard、Placemat 等。
  • CommandDispatcher 对 Undo/Redo 的统一性更好。

劣势

  • 学习曲线更陡，创建一个节点通常要写 Model + Processor，必要时还要 View。
  • 社区生态远弱于 xNode，踩坑基本靠自己。
  • 基于 Experimental GraphView，Unity 版本升级风险更高。
  • 示例和编辑器代码实际依赖 Odin，但包声明没有说明。

6. 风险与改进点

优先级问题证据建议
P0 Sirenix/Odin 依赖未声明 BaseGraphInspector、ObjectInspector、Examples 多处使用 Sirenix.*；package.json dependencies 为空。 要么声明 Odin 依赖与安装前提，要么把核心 Editor 的 Odin 依赖抽到可选 asmdef。
P0 package.json 仍有模板字段 author.url 是 https://github.com/Your_Name，keywords/description 是占位内容。 补全包描述、作者、关键字、依赖、samples/documentation 声明。
P1 基于 Experimental GraphView 大量引用 UnityEditor.Experimental.GraphView。 锁定支持 Unity 版本；若面向 Unity 6.x，新项目评估迁移 Graph Toolkit。
P1 Blackboard 用 GetHashCode 判断值是否变化 Blackboard.IDataContainer.cs 中比较 v.GetHashCode() == value.GetHashCode()。 改为 EqualityComparer<TValue>.Default.Equals(v, value)，并处理 null。
P1 ISetPortValue 方法名疑似错误 接口名是 Set，但方法为 GetValue(string portName, object value)。 保留兼容接口并标 Obsolete，迁移到已有的 IWritePortValue.SetValue。
P1 运行时执行语义缺失 现有 GetConnectionValue 是即时 pull 求值，没有统一 graph executor。 按业务建立 DataFlowExecutor / FlowExecutor / AbilityExecutor。
P2 子图只有导航，没有端口暴露协议 OpenSubgraph 和面包屑已具备，但没有输入/输出映射模型。 增加 SubgraphInput / SubgraphOutput 节点或 exposed port mapping。
P2 Samples~ 为空 真正示例在 Examples，不是 UPM 标准 Samples。 将 Math/Flow/Perf 整理成 Samples~，让 Package Manager 可导入。

推荐定位

如果这个包是给团队内部长期使用，我建议继续投入 PFGraph：它的结构底子不错，适合沉淀成内部技能编辑器、行为树编辑器、关卡逻辑图、数值管线图。 如果目标是快速上线一个简单对话/FSM 工具，xNode 成本更低。如果目标是稳定的数据处理图，NodeGraphProcessor 值得参考甚至直接采用。如果新项目锁定 Unity 6.4+，Unity Graph Toolkit 是更值得评估的官方方向。
